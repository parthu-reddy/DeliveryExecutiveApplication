# Integrating with the Payment Flow (Monolith)

The Payment Flow exposes robust APIs to process webhooks (specifically Vyapar for UPI). This document outlines how it functions within the monolithic food delivery ecosystem.

## 1. Creating a Payment Order

When a user initiates checkout, the `OrderController` validates the cart and initiates an Order with `OrderStatus.CREATED`. 

**Internal Flow:**
The monolith returns the standard `ApiResponse` with the newly created `Order` object. The frontend client application uses the internal `Order.id` as the transaction reference when initializing the payment SDK (like UPI intent apps).

## 2. Webhook Ingestion

The payment gateway calls the following endpoint:
- `POST /api/v1/webhooks/vyapar`

This endpoint verifies the cryptographic HMAC signature in constant-time using `RequestCachingFilter` and `WebhookController`. Once validated, the webhook passes the payload string to the `OrderSagaOrchestrator.handlePaymentSuccess()` method.

## 3. Listening for Payment Success

Since the monolith receives webhooks asynchronously, internal fulfillment logic must wait for the webhook to be processed.

**Integration Pattern:**
- `WebhookController` delegates to `OrderSagaOrchestrator`.
- `OrderSagaOrchestrator` updates the `Order` state to `PAID`.
- In the exact same Database Transaction, `LedgerService` credits the restaurant's `Ledger` account.
- The `OrderSagaOrchestrator` generates an `OutboxEvent` for asynchronous logistics dispatch, thereby completing the payment-to-fulfillment orchestration reliably within the monolith.

## 4. Idempotency Requirements

If you build an internal REST API endpoint in this service that modifies payment state, you *must* pass the `Idempotency-Key` HTTP header. 
- The key should be a unique UUID generated by the calling service.
- The `IdempotencyFilter` ensures that network retries don't duplicate ledger operations or order dispatches.

## Example: Using the SDK in a Frontend Client
Once the backend returns the `Order`, the frontend (Web/Android/iOS) initializes the respective gateway's SDK or UPI intent. The frontend *must not* be trusted to confirm payment success. Always rely on the backend webhook to trigger fulfillment.
